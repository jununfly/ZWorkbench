## 1. 名称身份与歧义

### 1.1 DeepSeek Harness

这是三者中名称最明确的对象。官方仓库根 README 直接写明 “DeepSeek Harness (`dsh`)” 由 DeepSeek AI 开发，并给出官方文档、npm 包和运行入口；根 `package.json` 的包名为 `@deepseek-ai/dsh-root`。因此纳入对象是 `deepseek-ai/deepseek-harness`，不是社区的 `awesome-deepseek-harness` 或把 DeepSeek 模型 SDK 当作 Harness。

### 1.2 Pi Agent Harness

名称在仓库历史和搜索结果中有别名歧义，但当前官方身份足够明确：`earendil-works/pi` 的根 README 标题就是 “Pi Agent Harness”，并将仓库边界拆成 `pi-coding-agent`、`pi-agent-core` 和 `pi-ai`。旧的 `badlogic/pi-mono` 是历史/迁移候选名，其 raw README 指向同一 Pi Agent Harness 内容；应以当前 canonical URL `earendil-works/pi` 固定版本，不把 `c4pt0r/pie`、`Dicklesworthstone/pi_agent_rust` 或其他 `pi-agent-harness` 社区仓库替代为上游对象。

### 1.3 Codex Harness

没有发现一个由 OpenAI 官方维护、仓库名正好为 `codex-harness` 的唯一项目。官方 OSS 对象是 `openai/codex`，其 README 的确切产品名是 “Codex CLI”，描述为“来自 OpenAI、在本机运行的 coding agent”；仓库还包含 `codex app-server`、官方 TypeScript/Python SDK、工具、沙箱和 rollout trace。因此本票据把“Codex Harness”映射为 `openai/codex`，但保留原名称歧义：

- 候选 A（纳入）：`openai/codex`，官方 OpenAI OSS CLI/app-server/SDK；见 [`README.md`](https://github.com/openai/codex/blob/63d213884daea50e4f74efc192cdc44f549b67d5/README.md)、[`app-server/README.md#L1-L4`](https://github.com/openai/codex/blob/63d213884daea50e4f74efc192cdc44f549b67d5/codex-rs/app-server/README.md#L1-L4)。
- 候选 B（不纳入）：`ganimjeong/Harness-for-codex`、`thu-nmrc/OpenHarness-For-Codex`、`chapzin/codex-harness-mcp` 等社区包装/扩展项目；它们不是 `openai` 官方仓库，不能代表 Codex 上游能力。
- 候选 C（边界外）：Codex Web/Desktop 或 ChatGPT 中的托管产品；官方 README 明确把 Codex CLI、本地 app 和云端 Codex Web 区分开来，因此不能把云端产品能力倒灌给 OSS 仓库。

## 3. DeepSeek Harness：逐项证据

1. **身份与边界。** 官方 README 明确是 DeepSeek AI 的开源 agent harness，采用 “everything-is-a-plugin”，运行入口是 `@deepseek-ai/dsh web`；架构文档将 model adapter、tool registry、session log、agent loop 都定义为可替换插件。见 [`README.md#L1-L27`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/README.md#L1-L27)、[`docs/architecture.md#L9-L29`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/architecture.md#L9-L29)。
2. **运行循环。** 一步是一次 model request 加其 tools；一轮由零个或多个 step 组成。规范化流程是 `turn/start → agent/pre-step → step/start → agent/request → llm/stream → tool/call → tools/pre-execute/execute/post-execute → tool/result → step/end → turn/end`；这些事件中一部分是 durable SessionEvent，另一部分是 live extension point。见 [`docs/architecture.md#L64-L101`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/architecture.md#L64-L101) 和 [`docs/agent-lifecycle.md#L19-L72`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/agent-lifecycle.md#L19-L72)。
3. **工具、工作区、状态。** `ctx.tools` 是 scoped registry 和 guarded execution pipeline；workspace 有独立实体/registry；session log 是 model context 的 source，`deriveMessages()` 从日志投影，raw assistant chunks 用于 replay/UI。见 [`docs/architecture.md#L49-L62`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/architecture.md#L49-L62)、[`docs/architecture.md#L103-L113`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/architecture.md#L103-L113)、[`docs/subsystems/workspace.md#L1-L21`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/subsystems/workspace.md#L1-L21)。
4. **代码闭环。** 工具包和文档给出 `fs`/write/edit、bash、code runtime、LSP、plan mode、Git hooks/集成、subagent 等证据；工具 schema 在执行前验证，支持 typed canonical result、超时/retry wrapper、approval、后台 job。见 [`docs/cookbook/adding-a-tool.md#L7-L65`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/cookbook/adding-a-tool.md#L7-L65)、[`docs/cookbook/extension-cookbook.md#L101-L129`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/cookbook/extension-cookbook.md#L101-L129)。存在这些包不等于每一种部署都启用，profile/bundle 决定实际组合。
5. **MCP/API/插件。** 架构是 Cordis profile/bundle/patch；官方 capability map 把 MCP 定义为“一服务器一插件，发现工具后注册到 `ctx.tools`”，并提供 API Gateway、SDK、ACP、webhook、dynamic workflow 等外接面。见 [`docs/architecture.md#L15-L47`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/architecture.md#L15-L47)、[`docs/cookbook/extension-cookbook.md#L101-L129`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/cookbook/extension-cookbook.md#L101-L129)、[`docs/api-gateway.md#L80-L125`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/api-gateway.md#L80-L125)。
6. **Provider。** `ctx.llm` 是 adapter seam；官方文档列出 `dsh-llm-deepseek` 和 `dsh-llm-pi-ai`，而 DeepSeek wire extension 只属于 DeepSeek provider，不会污染 provider-neutral interface。见 [`docs/architecture.md#L109-L137`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/architecture.md#L109-L137)、[`docs/deepseek-llm-api-wire-extensions.md#L1-L39`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/deepseek-llm-api-wire-extensions.md#L1-L39)。
7. **自动化/定时。** 这里有实际内建的 session-local schedule：支持 after/at/every（每条记录至少五分钟），持久化 `schedule/change`，重开 session 恢复 timer；但交付边界是原 live Session，cold session 不工作，也不是跨 session 的完整 cron 服务。另有 jobs/workflow/webhook/ACP 组合面。见 [`docs/subsystems/schedule.md#L1-L11`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/subsystems/schedule.md#L1-L11)、[`#L92-L102`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/subsystems/schedule.md#L92-L102)、[`#L154-L186`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/subsystems/schedule.md#L154-L186)、[`docs/subsystems/jobs.md#L155-L177`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/subsystems/jobs.md#L155-L177)。
8. **轨迹/回放/评测。** Session persistence 是 append-only durable event log；冷 session 中断时会补 synthetic interrupted `turn/end`，并保留物理尾部。官方 capability map 直接记录 `session/event → JSONL` 和 `sessions.create(id, { seed })` replay；benchmark 文档要求独立 workspace/session。见 [`docs/subsystems/persistence.md#L5-L19`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/subsystems/persistence.md#L5-L19)、[`docs/cookbook/extension-cookbook.md#L124-L129`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/cookbook/extension-cookbook.md#L124-L129)、[`BENCHMARK.md#L1-L4`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/BENCHMARK.md#L1-L4)。这证明日志重建/回放和 benchmark 入口，不证明模型外部效果可以 exactly-once 重放。
9. **沙箱/安全。** `dsh-sandbox-local` 提供 Linux bwrap/Landlock、macOS Seatbelt、Windows ACL restricted-token backend；`read-only`/`workspace-write`/`danger-full-access` 只定义文件效果，网络和 process visibility 不属于该词汇。官方安全说明同时明确：能执行模型生成的代码/命令、加载第三方插件、访问被授予的网络/进程/凭据/文件，未经过 security audit，不应视为 secure/production-ready。见 [`docs/subsystems/sandbox.md#L1-L38`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/docs/subsystems/sandbox.md#L1-L38)、[`SAFETY.md#L5-L23`](https://github.com/deepseek-ai/deepseek-harness/blob/cd5ef8148158c3a752a658978873241fdf8e2bbc/SAFETY.md#L5-L23)。

1. **身份与边界。** 官方根 README 把对象定义为本地运行的 OpenAI Codex CLI；`codex-app-server` README 明确其用途是给 VS Code 等 rich interfaces 提供接口。因此本节只讨论 `openai/codex` OSS checkout，不把 Codex Web/Desktop 的闭源或云端行为作为仓库能力。见 [`README.md`](https://github.com/openai/codex/blob/63d213884daea50e4f74efc192cdc44f549b67d5/README.md)、[`codex-rs/app-server/README.md#L1-L4`](https://github.com/openai/codex/blob/63d213884daea50e4f74efc192cdc44f549b67d5/codex-rs/app-server/README.md#L1-L4)。

- GitHub stars、forks、topic match 和由此产生的“热度/活跃度”未报告：canonical collector 被 rate limit 阻断，且没有旧 sealed ledger 可复用。只有 commit/tag/release 文档锚点被保留。
- 外部插件、MCP server、provider adapter、container/microVM、云端执行器的实际许可证、供应链、凭证处理和维护责任需要按具体集成逐项复核；根仓库许可证不能替代这些核验。
