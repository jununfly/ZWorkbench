# ADR 0004：宿主交互证据来自经 CDP 驱动的本机浏览器

## Context

键盘焦点顺序、指针事件穿透、剪贴板失败可见性与关闭后的焦点恢复，都无法由状态机断言。它们
是渲染引擎的行为，只有真实浏览器能给出证据。若没有取证途径，这些面将长期停在 `unknown`，
而结构覆盖满格会被误读为验收通过。

通用浏览器自动化库能提供这种能力，但会带来安装、浏览器下载、驱动版本对齐与联网获取的负担，
而本项目只需要少量协议方法。

## Decision

交互证据由本机既有浏览器经 Chrome DevTools Protocol 的稳定域产生，驱动代码使用标准库自建，
只覆盖导航、求值、输入派发、视口模拟与权限五类所需能力。不引入浏览器自动化库，不新增第三方
运行时依赖，不下载或分发浏览器二进制。

浏览器是验证期外部工具。它不可用时，依赖它的验收面保持 `unknown`。

## Consequences

- 浏览器缺席时相关测试跳过并保留 `unknown`，不得改判为通过或不适用；跳过原因必须出现在报告中。
- 证据必须携带运行时实测的浏览器版本与协议版本。版本变化时重跑受影响验证，不继承旧证据。
- 浏览器夹具只以上下文管理器或测试清理钩子暴露。失败路径若不经清理会留下存活的子进程与临时
  用户目录，因此不提供可直接构造的裸实例。
- 剪贴板拒绝在无头环境中无法自发产生，只能以注入方式构造。此类证据必须标注为注入拒绝，其结论
  限于"拒绝发生时界面可见且不自动重试"，不覆盖真实用户拒绝场景。
- 视口模拟须在导航完成之后施加。次序颠倒会得到退化视口，使命中测试在无声中失去意义。
- 更换验证引擎只需取代本 ADR，不牵动宿主形态的决定。
